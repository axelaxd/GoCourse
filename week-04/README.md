# Неделя 4. Дженерики. Ошибки и их обработка. Паники

Дженерики - это способ сделать код более универсальным, чем он есть, через написание функций и типов, работающих с разными типами данных, сохраняя типобезопасность

1. Рассмотрим, какую проблему решили дженерики:

```go
// Функция для поиска максимума int
func MaxInt(a, b int) int {
    if a > b {
        return a
    }
    return b
}

// Функция для поиска максимума float64
func MaxFloat64(a, b float64) float64 {
    if a > b {
        return a
    }
    return b
}

// Функция для поиска максимума string
func MaxString(a, b string) string {
    if a > b {
        return a
    }
    return b
}

// Дублирование кода!
```

Теперь эти три функции можно объединить в одну:

```go
import (
	"fmt"
	"cmp"
)

func Max[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func main() {
	fmt.Println(Max(10, 20)) // 20
	fmt.Println(Max(3.14, 2.71)) // 3.14
	fmt.Println(Max("hello", "world")) //world
}
```

То есть функция  `Max` превратилась в **обобщённую функцию**, которая может работать с более чем одним типом. Описывается такая функция следующим синтаксисом:

- `[T cmp.Ordered]` - обобщённый параметр с наложенным ограничением на тип
- `T` - имя параметра типа (может быть любой буквой)
- `cmp.Ordered` - ограничение на тип

	Иными словами, мы описываем для функций некий **абстрактный тип**

В нашем случае функция может может принимать две переменные `a` и `b` одного и того же типа `T`, который, в свою очередь, должен отвечать **требованиям ограничений**

```go
// Функция с двумя параметрами типов
func Map[T, U any](slice []T, fn func(T) U) []U {
    result := make([]U, len(slice))
    for i, v := range slice {
        result[i] = fn(v)
    }
    return result
}
```

Но не функциями едиными. Можно создать еще и обобщённые структуры:
```go
package main

import "fmt"

// Обобщённая структура для пары значений
type Pair[K, V any] struct {
    Key   K
    Value V
}

func main() {
    p1 := Pair[string, int]{Key: "age", Value: 30}
    p2 := Pair[int, string]{Key: 1, Value: "first"}
    
    fmt.Println(p1) // {age 30}
    fmt.Println(p2) // {1 first}
}
```

2. `Ограничения параметров`
	Мы можем вручную ограничить обобщённые параметры. 
	
	Это означает, что мы можем указать, **какие именно типы** может представлять параметр в функции.

В Go, **подобные ограничения** уже имеются у нас на руках:

- `any` - для типа не существует никаких ограничений
- `comparable` - позволяет работать только со сравниваемыми типами (которе работают с операторами ``` и `!=`)
- `cmp.Ordered` - дает возможность работать только с упорядоченными типами (которые работают со знаками неравенства `>`, `<`, `>=`, '<=`)

Но не только встроенными ограничениями мы пользуемся

```go
// Ограничение: тип должен иметь метод String()
type Stringer interface {
    String() string
}

func PrintAll[T Stringer](items []T) {
    for _, item := range items {
        fmt.Println(item.String())
    }
}
```

Еще в интерфейсе можно указать конкретный набор типов, которые бы был готов видеть в обобщённом параметре. Например:

```go
type Number interface {
	int | float64
}

func Sum[T Number](numbers []T) T {
	var sum T
	for _, n := range numbers {
		sum += n
	}

	return sum
}
```

Оператор `|` по сути и является тем самым `И`, которое помогает компилятору понять, что перечень типов в интерфейсе является ограничением для дженерика

3. **Перечислить все подтипа одного типа** `~`
	Это тот оператор, который является "приближённым ограничением"

	Означает, что в дженерике может использоваться конкретный тип и все типы, для которых он является базовым

```go
type Integer interface {
	~int
}

type MyInt int
  
func Double[T Integer](value T) T {
	return value * 2
}

func main() {
	var x int = 5
	var y MyInt = 10

	fmt.Println(Double(x)) // 10
	fmt.Println(Double(y)) // 20
}
```

И это отлично работает! В целом работа с ограничениями дженериков достаточно гибкий механизм. Даже `cmp.Oredered` - это набор базовых типов:

```go
type Ordered interface {
	~int | ~int8 | ~int16 | ~int32 | ~int64 |
		~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr |
		~float32 | ~float64 |
		~string
}
```

#### Где дженериков пока нет

```go
type Container[T any] struct {
    value T
}

// ✅ Метод использует T из структуры
func (c Container[T]) Get() T {
    return c.value
}

func (c *Container[T]) Set(value T) {
    c.value = value
}

// ❌ ОШИБКА: метод не может иметь свои параметры типов
// func (c Container[T]) Convert[U any](fn func(T) U) U {
//     return fn(c.value)
// }
```

#### Использование дженериков

Дженерики лучше использовать в следующих случаях:

1. Для сложных структур данных — списков, стеков, деревьев, графов.
2. Для утилитных функций — Map, Filter, Reduce.
3. Для обобщённых алгоритмов — сортировка, поиск.
4. Когда избегаешь дублирования кода для разных типов.

А не использовать в таких ситуациях:

5. Когда достаточно интерфейсов: в случае если нужно поведение, а не тип.
6. Для простых функций, если тип известен.

В целом вырисовывается перечень правил работы с дженериками:

- Начинай с конкретных типов, обобщай позже.
- Используй понятные имена: T, K, V для простых случаев.
- Ограничивай типы.
- Предпочитай интерфейсы, когда нужно поведение.
- Не злоупотребляй, потому что простота важнее универсальности.

### Ошибки

Ошибки - это не просто условия для поверки, а **значения**, которые имеют свой тип, с которыми можно работать так же, как и с любыми другими данными

```go
_, err := fmt.Scan(&x)

if err != nil {
	fmt.Println(err)
}
```

Самое важное, что мы должны всегда помнить: **обрабатывать ошибки нужно всегда**

Итак, что такое ошибка в Go? Это значение. Но ещё это **интерфейс**!
```go
type error interface {
	Error() string
}
```

То есть всякий тип, который удовлетворяет этому интерфейсу, может быть ошибкой. А значит с ошибками можно работать по-разному:

**Во-первых**, можно добавлять ошибке контекст, Добавив такие параметры, как:

- параметры функции;
- значения переменных;
- дополнительные сообщения об ошибках;

Одним из способов обогатить ошибку является использование пакета `fmt`. Функция `Errorf` добавляет форматированное описание функции:

```go
return fmt.Error("Ошибка при обработке юзера %s: %w", UserID, err)
```

Тут мы уже существующей ошибке `err` **добавляем уровень контекста**. 
`%w` - этот глагол форматирования позволяет в дальнейшем извлечь **исходное сообщение** об ошибке


**Во-вторых**, раз мы можем оборачивать ошибки, то можем и раскрывать их. Для этого используется пакет стандартной библиотеки `errors`. А именно метод `errors.Is`

```go
if err != nil && errors.Is(err, "какая-то ошибка"){
	fmt.Println("тут ошибка")
}
```

Метод позволяет отыскать в цепочке ошибок **ту самую** нужную.

**В-третьих**,  можно создавать ошибки. Делается это просто, через тот же пакет `errors`:

```go
var ErrInvalidArgument = errors.New("Invalid argument")
```

```go
func checkArgument(a int) error {
	if a == 0 {
		return ErrInvalidArgument
	}
	
	return nil
}
```

Важно еще и то, что подобные sentinel-ошибки **должны начинаться** с префикса `Err...` или `err...` при объявлении

**В-четвертых**, раз наши ошибки могут быть любым типом, удовлетворяющему интерфейсу `Error`, можно проверять существование конкретного типа у ошибки через метод `error.As`:

```go
type MyError struct {
	Code int
	Msg  string
}

func (e *MyError) Error() string {
	return fmt.Sprintf("Ошибка %d: %s", e.Code, e.Msg)
}

func doSomething() error {
	return fmt.Errorf("дело дрянь: %w", &MyError{Code: 500, Msg: "Сервер недоступен"})
}

func main() {
	var targetErr *MyError
	
	err := doSomething()
	if errors.As(err, &targetErr) {
		fmt.Println("Код ошибки:", targetErr.Code, "Сообщение:", targetErr.Msg)
	} else {
		fmt.Println("Произошла неизвестная ошибка")
	}
}
```

В новой версии языка 1.26 подобный синтаксис упростили:
```go
pathError, ok := errors.AsType[*fs.PathError](err)
```

3. **Отложенные вызовы** - `defer`
	Позволяет отложить выполнение функций, пока не завершится выполнение функции, в чьём теле они существуют.

	Можно, например, писать о закрытии соединения рядом с его открытием.

В теле любой функции можно вызвать неограниченное кол-во `defer`. Они будут выполняться по принципу `LIFO` - последним пришел, первым ушел

```go
func Example() {
    for i := 3; i > 0; i-- {
        defer fmt.Print(i, " ") 
        // Используем существующую функцию + выведется ответ, обратный объявлению, то есть `1 2 3`
    }
}

func Example3() {
    for i := 3; i > 0; i-- {
        defer func(n int) {    // Анонимная функция
            fmt.Print(n, " ")
        }(i)
    }
}
```

Использование `defer`, по сути, гарантирует, что в случае возникновения ошибок, мы в любом случае выполним код, который есть у `defer` (несмотря на ошибки)

4. **Паники не ошибки** - `panic`
	В Go есть аналоги необрабатываемых исключений из других языков. И это "паника", которая вызывается через `panic()`

	По сути, это фатальная ошибка в коде, приложение падает, выдавая в стандартный вывод ошибок стек вызова с **описанием местоположения** паники.


5. **Ловец паник** - `recover`
	Паники можно перехватить, обработать и продолжить выполнение программы как ни в чем не бывало.

	И это можно сделать с помощью функции `recover()` вместе с `defer`

	`recover` работает, только если она вызывается внутри `defer`. Иначе функция просто возвращает значение, переданное в `panic`

```go
package main

import (
	"fmt"
)

func Example() {
	fmt.Println("Inside function")
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("Recovered:", r)
		}
	}()
	panic("Panic!")
}

func main() {
	Example()
	fmt.Println("Main function continues")
}
```

Вывод тут будет следующим:
```
Inside function
Recovered: Panic!
Main function continues
```
