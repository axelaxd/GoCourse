# Неделя 6. Конкурентность и параллелизм

`Параллелизм` - это процесс выполнения нескольких задач одновременно на разных ядрах процессора

`Конкурентность` - псевдопараллельность, когда задачи выполняются на одном и том же ядре, которое постоянно переключает их выполнение между собой

1. **Как работать с горутинами** - `go`
	Горутины создаются посредством использования специального слова `go`, которое указывает, что следующая за ним функция будет выполняться независимо от основной горутины (`main`), конкурентно

```go
package main
import (
    "fmt"
    "time"
)

func sayHello(name string) {
	fmt.Printf("Привет, %s!\n", name)
}

func main() {
    fmt.Println("Начинаем программу...")
    
    // Запускаем первую горутину
    go sayHello("Анна")
    
    // Запускаем вторую горутину
    go sayHello("Борис")
    
    fmt.Println("Программа завершена")
}
```

Что выдаст это программа? А вот что:

```
Начинаем программу...
Программа завершена
```

Довольно неожиданно. Так вот, горутинам необходимо время на выполнение функций. Поэтому, если поставить `time.Sleep()`  перед `fmt.Println`, то мы получим ожидаемый результат

❗ Горутины могут работать в разной последовательности. И это **очень важно**, так как спецификация языка не гарантирует порядка выполнения горутин

Но также горутины могут работать и с анонимными функциями

```go
package main

import (
    "fmt"
    "time"
)

func sayHello(name string) {
	fmt.Printf("Привет, %s!\n", name)
}

func main() {
    fmt.Println("Начинаем программу...")
    
    // Запускаем 1 горутину
    go func() {
    	fmt.Println("Анна")
    }()  // У анонимных функция не забываем ставить () в конце объявления, что означает их готовность к запуску
    
    // Запускаем вторую горутину
    go sayHello("Борис")
    
    fmt.Println("Программа завершена")
}
```

#### Концепция планировщика
- С помощью переменной `GOMAXPROCS` мы можем задать количество ядер, которые будут доступны нашей программе

```go
func main() {
    // Использовать только одно ядро — чистый конкурентный код
    runtime.GOMAXPROCS(1)
    
    // Использовать все доступные ядра (по умолчанию). Если ядер >2, то код и конкурентный, и параллельный одновременно
    runtime.GOMAXPROCS(runtime.NumCPU())
    
    // В Go 1.5+ это значение по умолчанию равно количеству ядер
}
```

2. **Каналы между горутинами** - `make`
	Каналы объявляются через `make` с указанием типа канала и могут быть буферезированными и небуферезированными (число после запятой с определением типа)

	`make(chan int, \<value>)` - задает буфер

	**Буферезированный** - асинхронная передача данных

	**Небуферезированный** - не асинхронно


```go
package main

import (
	"fmt"
	"time"
)

func main() {
    ch := make(chan int) // Небуферезированный канал
    
    go func() {
        fmt.Println("Горутина 1: готова отправить")
        ch <- 42  // Блокируется пока горутина 2 не начнёт приём
        fmt.Println("Горутина 1: данные отправлены")
    }()
    
    time.Sleep(1 * time.Second)
    
    fmt.Println("Горутина 2: готова принять")
    value := <-ch  // Разблокирует горутину 1
    fmt.Printf("Горутина 2: получено значение %d\n", value)
}
```

Оператор `<-` -  это оператор чтения/записи в канал

#### Работа с каналами
В каналы можно писать и из них можно читать. Это можно делать как по одной операции, так и в цикле:

```go
// Чтение из канала в цикле

for {
    val, ok := <-ch  // Второй параметр — признак закрытия канала
    if !ok {
    	break
    }
    fmt.Println(val)
}

// Запись в канал в цикле
for range n {
	ch <- n
}
```

В примере мы видим ok-нотацию. Она нужна для того, чтобы проверять в цикле, закрыт ли канал или нет. Да, каналы можно закрывать с помощью встроенной функции `close():`

```go
// Запись в канал в цикле
for range n {
    ch <- n
}

close(ch) // Закрываем канал после записи
```

Каналы надо закрывать в момент, когда в них отпадает необходимость

**Важное правило**: каналы закрывает та горутина, которая в нее пишет. Поэтому, когда создаешь канал, **сразу понимай, когда и где ты его закроешь**

❗**Принимающие горутины должны всегда проверять канал на закрытие**, если логикой предусмотрена такая возможность. Исключением является использование `for range` у канала (сам проверяет)

```go
// Чтение из канала в цикле
for val := range ch {
    fmt.Println(val)
}
```

4. **Мультиплексирование каналов** - `select case`
	Необходим для одновременного взаимодействия каналов

	`select` **блокируется, ожидая ответа** из одного из своих кейсов в рандомном порядке.
	
	 **Деблокировать** `select` можно через оператор `default`, который выполнится, если ни один из `case` не готов к выполнению

```go
package main

import (
	"fmt"
	"time"
)

func main() {
    ch1 := make(chan string)
    ch2 := make(chan int)
    timeout := make(chan bool)
    
    // Отправитель 1
    go func() {
        time.Sleep(2 * time.Second)
        ch1 <- "из канала 1"
    }()
    
    // Отправитель 2
    go func() {
        time.Sleep(1 * time.Second)
    ch2 <- 100
    }()
    
    // Таймаут
    go func() {
        time.Sleep(3 * time.Second)
        timeout <- true
    }()
	
    for {
    select {
        case msg1 := <-ch1:
            fmt.Printf("Получено из канала 1: %s\n", msg1)
        case msg2 := <-ch2:
            fmt.Printf("Получено из канала 2: %d\n", msg2)
        case <-timeout:
            fmt.Println("Таймаут!")
            return
        default:
            fmt.Println("Ни один канал не готов, делаем другую работу...")
            time.Sleep(1 * time.Second)
        }
    }
}
```

5. **пустые каналы** - `nil`
	Если канал nil, значит что канал объявлен, но не инициализирован. 
	
	Такие каналы имеют особое поведение: **все операции с ними блокируются навсегда**. Причем закрытие такого канала вызовет панику

	**Зачем нужны?** Самый частый кейс - **сделать из обычного канала** `nil` -канал в моменте, чтобы `select` перестал рассматривать `case` с этим каналом в качестве рабочего

6. **Блокировки каналов**
	`Deadlock` (взаимная блокировка) - это ситуация, когда **все горутины в программе заблокированы** и ждут событий, которые никогда не произойдут. 
	
	В Go runtime автоматически обнаруживает такие ситуации и вызывает панику

```
func channelDeadlock() {
    ch := make(chan int)
    // Deadlock: горутина пытается отправить в канал, но нет получателя
    
    ch <- 42  // Это заблокирует навсегда
    
    fmt.Println("Эта строка никогда не выполнится")
}
```

7. **Гонки данных и гонки состояний** - `race condition`
	**Race condition** — гонка состояний, являющаяся ошибкой, при которой результат работы системы зависит от непредсказуемого порядка выполнения процессов (в нашем случае горутин)
	
```go
// ❌ Небезопасный инкремент
func simpleRaceCondition() {
    counter := 0
    
    go func() {
        counter = 1
    }()
    
    go func() {
    	counter = 100
    }()
    
    time.Sleep(1*time.Second)
    
    fmt.Printf("Результат: %d\n", counter)
    // Результат будет непредсказуемым: 1 или 100
}
```

8. Отслеживание гонок в Go

```go
# Запуск программы с детектором
go run -race main.go

# Запуск тестов с детектором
go test -race ./...

# Сборка с детектором
go build -race main.go
```
