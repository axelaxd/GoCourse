## Ответы на вопросы

### Какую проблему решают generics?

Позволяют написать алгоритм или контейнер один раз для семейства типов,
сохраняя статическую типизацию. Это уменьшает дублирование без перехода
к `any` и постоянным type assertions.

### Что такое параметр типа и constraint?

Параметр типа объявляется в `[]`, например
`func Max[T cmp.Ordered](a, b T) T`. Constraint ограничивает множество
типов и операции, которые разрешено выполнять над `T`.

### Чем отличаются `any`, `comparable`, `cmp.Ordered`?

`any` допускает любой тип. `comparable` допускает типы, значения которых
можно сравнивать `==` и `!=`, поэтому такой `T` можно, например,
использовать как ключ map. `cmp.Ordered` ограничивает типы теми, для
которых определён естественный порядок `< <= >= >`.

### Что означает `~int` в type set?

`~int` означает все типы, whose underlying type --- `int`, включая
defined types вроде `type UserID int`. Это позволяет constraint
принимать не только сам `int`.

### Когда лучше interface, а когда generic?

Interface выбирают, когда важна **динамическая абстракция поведения**:
функции нужны определённые методы объекта. Generics --- когда один и тот
же алгоритм должен работать со многими статически известными типами и
возвращать/сохранять конкретный тип без type assertions.

------------------------------------------------------------------------

Дженерики - это способ сделать код более универсальным, чем он есть,
через написание функций и типов, работающих с разными типами данных,
сохраняя типобезопасность

1.  Рассмотрим, какую проблему решили дженерики:

```{=html}
<!-- -->
```
    // Функция для поиска максимума int
    func MaxInt(a, b int) int {
        if a > b {
            return a
        }
        return b
    }

    // Функция для поиска максимума float64
    func MaxFloat64(a, b float64) float64 {
        if a > b {
            return a
        }
        return b
    }

    // Функция для поиска максимума string
    func MaxString(a, b string) string {
        if a > b {
            return a
        }
        return b
    }

    // Дублирование кода!

Теперь эти три функции можно объединить в одну:

    import (
        "fmt"
        "cmp"
    )

    func Max[T cmp.Ordered](a, b T) T {
        if a > b {
            return a
        }
        return b
    }

    func main() {
        fmt.Println(Max(10, 20)) // 20
        fmt.Println(Max(3.14, 2.71)) // 3.14
        fmt.Println(Max("hello", "world")) //world
    }

То есть функция `Max` превратилась в **обобщённую функцию**, которая
может работать с более чем одним типом. Описывается такая функция
следующим синтаксисом:

-   `[T cmp.Ordered]` - обобщённый параметр с наложенным ограничением на
    тип

-   `T` - имя параметра типа (может быть любой буквой)

-   `cmp.Ordered` - ограничение на тип

    Иными словами, мы описываем для функций некий **абстрактный тип**

В нашем случае функция может может принимать две переменные `a` и `b`
одного и того же типа `T`, который, в свою очередь, должен отвечать
**требованиям ограничений**

    // Функция с двумя параметрами типов
    func Map[T, U any](slice []T, fn func(T) U) []U {
        result := make([]U, len(slice))
        for i, v := range slice {
            result[i] = fn(v)
        }
        return result
    }

Но не функциями едиными. Можно создать еще и обобщённые структуры:

    package main

    import "fmt"

    // Обобщённая структура для пары значений
    type Pair[K, V any] struct {
        Key   K
        Value V
    }

    func main() {
        p1 := Pair[string, int]{Key: "age", Value: 30}
        p2 := Pair[int, string]{Key: 1, Value: "first"}
        
        fmt.Println(p1) // {age 30}
        fmt.Println(p2) // {1 first}
    }

2.  **Ограничения параметров** Мы можем вручную ограничить обобщённые
    параметры.

    Это означает, что мы можем указать, **какие именно типы** может
    представлять параметр в функции.

В Go, **подобные ограничения** уже имеются у нас на руках:

-   `any` - для типа не существует никаких ограничений
-   `comparable` - позволяет работать только со сравниваемыми типами
    (которе работают с операторами `==` и `!=`)
-   `cmp.Ordered` - дает возможность работать только с упорядоченными
    типами (которые работают со знаками неравенства `>`, `<`, `>=`,
    '\<=\`)

Но не только встроенными ограничениями мы пользуемся

    // Ограничение: тип должен иметь метод String()
    type Stringer interface {
        String() string
    }

    func PrintAll[T Stringer](items []T) {
        for _, item := range items {
            fmt.Println(item.String())
        }
    }

Еще в интерфейсе можно указать конкретный набор типов, которые бы был
готов видеть в обобщённом параметре. Например:

    type Number interface {
        int | float64
    }

    func Sum[T Number](numbers []T) T {
        var sum T
        for _, n := range numbers {
            sum += n
        }

        return sum
    }

Оператор `|` по сути и является тем самым `И`, которое помогает
компилятору понять, что перечень типов в интерфейсе является
ограничением для дженерика

3.  **Перечислить все подтипа одного типа** **\~** Это тот оператор,
    который является "приближённым ограничением"

    Означает, что в дженерике может использоваться конкретный тип и все
    типы, для которых он является базовым

```{=html}
<!-- -->
```
    type Integer interface {
        ~int
    }

    type MyInt int
      
    func Double[T Integer](value T) T {
        return value * 2
    }

    func main() {
        var x int = 5
        var y MyInt = 10

        fmt.Println(Double(x)) // 10
        fmt.Println(Double(y)) // 20
    }

И это отлично работает! В целом работа с ограничениями дженериков
достаточно гибкий механизм. Даже `cmp.Oredered` - это набор базовых
типов:

    type Ordered interface {
        ~int | ~int8 | ~int16 | ~int32 | ~int64 |
            ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr |
            ~float32 | ~float64 |
            ~string
    }

#### Использование дженериков

Дженерики лучше использовать в следующих случаях:

1.  Для сложных структур данных --- списков, стеков, деревьев, графов.
2.  Для утилитных функций --- Map, Filter, Reduce.
3.  Для обобщённых алгоритмов --- сортировка, поиск.
4.  Когда избегаешь дублирования кода для разных типов.

А не использовать в таких ситуациях:

5.  Когда достаточно интерфейсов: в случае если нужно поведение, а не
    тип.
6.  Для простых функций, если тип известен.

В целом вырисовывается перечень правил работы с дженериками:

-   Начинай с конкретных типов, обобщай позже.
-   Используй понятные имена: T, K, V для простых случаев.
-   Ограничивай типы.
-   Предпочитай интерфейсы, когда нужно поведение.
-   Не злоупотребляй, потому что простота важнее универсальности.
