## Ответы на вопросы

### Почему `[3]int` и `[5]int` --- разные типы?

Размер массива является частью его типа. Поэтому `[3]int` и `[5]int`
нельзя напрямую присвоить друг другу или сравнить между собой как
значения одного типа.

### Что такое `len` и `cap`?

Для slice `len` --- количество доступных элементов, а `cap` --- сколько
элементов можно разместить от начала текущего slice до конца его
underlying array без перевыделения памяти. Для массива `len == cap`.

### Что делает `append`, когда `len < cap` и когда `len == cap`?

Если capacity достаточно, `append` обычно записывает новый элемент в
существующий underlying array и увеличивает длину возвращаемого slice.
Если места недостаточно, runtime выделяет новый массив, копирует
элементы и возвращает slice, указывающий уже на него. Конкретный
алгоритм роста capacity --- деталь реализации, на него нельзя
полагаться.

### Почему результат `append` нужно присваивать обратно?

`append` возвращает новый slice header. Даже если underlying array
остался прежним, изменилась длина; а при нехватке capacity мог
измениться и указатель на массив. Поэтому правильно: `s = append(s, x)`.

### Чем nil slice отличается от пустого?

`var s []int` --- nil slice: `s == nil`, `len(s) == 0`, `cap(s) == 0`.
`s := []int{}` --- non-nil empty slice: `s != nil`, но длина тоже 0. Для
`append`, `range` и `len` они обычно ведут себя одинаково; различие
иногда заметно при сериализации/API.

### Как работает `copy`?

`copy(dst, src)` копирует элементы из `src` в `dst` и возвращает их
количество. Копируется `min(len(dst), len(src))` элементов; capacity
назначения сама по себе длину не увеличивает.

2.  **Длина и ёмкость массива** - **len** и **cap** **len** - функция,
    которая возвращает длину значения, то есть количество элементов в
    типе, которые он в себе непосредственно содержит;

    **cap** - функция, которая возвращает ёмкость значения, то есть
    максимальное количество элементов, которое тип может содержать

> [!NOTE] В случае с массивом мы имеем соответствие len(x) == cap(x)

```go
    fruits := [4]string{
        "яблоко", "банан",
        "апельсин", "груша",
    }

    // С индексом и значением
    for index, fruit := range fruits {
        fmt.Printf("%d. %s\n", index+1, fruit)
    }

    // Только значения
    for _, fruit := range fruits {
        fmt.Println("Фрукт: ", fruit)
    }
      
    // Только индексы
    for index := range fruits {
        fmt.Printf("Индекс %d\n", index)
    }
```

#### Ограничения массивов

-   **Фиксированный размер**: после объявления массива изменить его
    размер нельзя;
-   **Размер - часть типа**: \[10\]int и \[20\]int несовместимы;
-   **Копирование при передаче**: дорого для больших массивов.

3.  **Гибка альтернатива массивам** - **слайсы** **Отличие**: слайсы
    имеют динамический размер;

    Слайс не имеет длины как часть типа, и объявляется без числа в
    квадратных скобках


```go
    var numbers []int // Пустой слайс целых чисел
    var names []string // Пустой слайс строк
```

-   Истинно пустой массив можно создать иначе: `empty := []int{}`

##### Новый вариант создания

-   Через новую функцию make, являющуюся идиоматичным способом
    объявления слайсов.

    Принимает на вход тип слайса, который надо создать, кол-во элементов
    этого слайса и общую ёмкость

```go
    // make([]T, length)
    numbers := make([]int, 5) // [0 0 0 0 0], len=5, cap=5

    // make([]T, length, capacity)
    buffer := make([]int, 0, 10) // [], len=0, cap=10
```

> [!NOTE] В отличии от массива, len вернет нам кол-во элементов в
> слайсе (заполненных индексов)

4.  **Функция для увеличения слайла** - **append**

```go
    var shopping []string

    shopping = append(shopping, "хлеб")
    shopping = append(shopping, "молоко", "яйца")

    fmt.Println(shopping)
    fmt.Println(len(shopping))

    # [хлеб молоко яйца]
    # 3
```

❗append возвращает новый слайс! Поэтому результат его вычисления нужно
присваивать обратно переменой, которую мы расширяем. Но что происходит
под капотом?

1.  Если в слайсе есть свободное место (`len < cap`), слайс не
    расширяется и `append` дописывает элемент в слайс, увеличивая длину.
2.  Если места нет (len == cap), создаётся новый слайс, туда копируются
    старые элементы и добавляется новый

**Отличие слайсов от массивов №3**: слайсы несравниваемый тип, в отличие
от массивов

Отличие слайсов от массивов №4: массив остается массивом, слайс/срез
можно брать от массива и от слайса

```go
    months := [12+1]string{
        "", "January", "February", "March", "April", "May", "June",
        "July", "August", "September", "October", "November", "December",
    }

    var (
        allMonths = months[:]
        firstHalf = months[1 : 6+1]
        secondHalf = months[7:]
        summer = months[6: 8+1]
    )

    fmt.Println(allMonths)
    fmt.Println("Лето:", summer)
    fmt.Println("Первая половина:", firstHalf)
    fmt.Println("Вторая половина:", secondHalf)
```

Синтаксис среза **\[start:end\]** означает "взять элементы с индекса"
`start` до индекса `end`, не включая `end`. Если старт опущен - берем с
начала, если `end` опущен - до конца. Все эти слайсы ссылаются на **один
и тот же** базовый массив

    summer[0] = "ИЮНЬ"                         // Изменяем слайс
    fmt.Println("Исходный массив:", months[6]) // ИЮНЬ - массив изменился!
    fmt.Println("Первая половина:", firstHalf[6-1]) // ИЮНЬ - изменилось!

> \[!NOTE\] Это показывает, что если изменить элемент через один слайс,
> то это сразу повлияет на базовый массив и станет видно по всех
> остальных слайсах!

5.  **Скопировать слайс** - **copy**

```go
    original := []string{"a", "b", "c", "d", "e"}

    // ОБЯЗАТЕЛЬНО создаем слайс-получатель через make
    destination := make([]string, len(original))

    // Копируем элементы
    n := copy(destination, original)
    fmt.Printf("Скопировано %d элементов\n", n) // 5

    // Изменяем копию — оригинал не изменится
    destination[0] = "MODIFIED"

    fmt.Println("Оригинал:", original)     // [a b c d e]
    fmt.Println("Копия:   ", destination)  // [MODIFIED b c d e]
```
