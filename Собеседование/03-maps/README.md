## Ответы на вопросы

### Как создать map через `make`?

Например: `m := make(map[string]int)`. Можно передать приблизительную
начальную ёмкость: `make(map[string]int, 100)`, но это не фиксированный
размер.

### Как читать значение с `comma-ok`?

`v, ok := m[key]`. `v` получает значение или zero value типа значения, а
`ok` сообщает, существовал ли ключ.

### Что происходит при чтении отсутствующего ключа?

Паники нет: возвращается zero value типа значения. Поэтому, если zero
value может быть настоящим значением в map, для различения нужен
`comma-ok`.

### Можно ли писать в nil map?

Нет. Чтение из nil map допустимо, `len` равен 0, `range` ничего не
выполнит, но запись `m[k] = v` приведёт к runtime panic. Перед записью
map нужно инициализировать.

### Почему обычная map требует синхронизации при конкурентной записи?

Обычная map не предназначена для несинхронизированных конкурентных
записей. Доступ нужно координировать, например `sync.Mutex`/`RWMutex`,
либо выбрать другую подходящую архитектуру. Иначе возможна data race и
runtime может завершить программу с ошибкой concurrent map access.

7.  **Встроенные хеш-таблицы**: **map** Это еще один встроенный тип
    данных, предназначенный для хранения ассоциативных данных в виде
    пары **ключ - значение**


```go
    var m map[int]string
```

> [!NOTE] 
> В примере выше важно то, что мапа хоть и объявлена, но не
> инициализирована. То есть она имеет значение nil, в случае попытки
> записи в такую мапу получим ошибку.

##### Работа с мапами

    m1 := make(map[int]bool) // Пустая
    m2 := make(map[bool]int, 10) // Инициалиированная
    m3 := map[float32]bool{1.2: true, 1.5: false} // Со значениями

-   Чтение и запись осуществляются тривиально - через обращение по
    ключу. Удаление ключа происходит через встроенную функцию `delete`

**Как проверить существования ключа?** - Нужно проверить существование
ключа через нотацию `value-ok`, где ok - это булевое значение;

```go
    m := make(map[int]bool)
    m[1] = true // Запись
    fmt.Println(m[1]) // Чтение: true
    delete(m, 1) // Удаление

    v, ok := m[2] // v = это всегда значение по ключу
    if !ok {
        fmt.Println("ключа нет!")
    }

    var m1 map[int]int

    fmt.Println(len(m1), len(m)) // 0 получим
```

> [!NOTE] 
> Хорошей практикой является проверять мапу не на nil, а на длину

    for k, v := range m { // k - ключ, v - значения. Получение рандомно
        fmt.Println(k, v)
    }
    fmt.Println(m) // Всегда один и тот же порядок данных

## Идиоматика из tooling-конспекта

#### nil мапы и слайсы

Встроенная функция `len()` спокойно может работать с
неинициализированными сущностями, просто возвращая 0. Таким образом,
вместо двух проверок на `nil` и пустоту, мы можем ограничиться только
одной - через `len()`

```go
    func AnyDo() { // Проверки дают одинаковый результат
      var sl []int
      
      if len(sl) == 0 {
        return
      }
      
      if sl == nil {
        return
      }
      ...
    }
```

Хорошим тоном считается инициализировать слайсы именно через `var`, а не
`sl := \[]int{}`
