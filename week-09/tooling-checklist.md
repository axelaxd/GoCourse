# Быстро повторить: Go tooling перед PR

[← К полной неделе](./README.md) · [↑ К содержанию курса](../README.md)

## Общая идея

В конспекте процесс сформулирован так:

```text
пишем код
→ форматируем
→ статические проверки
→ тесты
→ commit / review
```

## Форматирование

Стандартный форматтер:

```bash
gofmt -w .
```

или:

```bash
go fmt ./...
```

`goimports` дополнительно работает с импортами:

```bash
goimports -w .
```

## `go vet`

Ищет подозрительные и потенциально ошибочные конструкции:

```bash
go vet ./...
```

При этом `go vet` не гарантирует отсутствие всех проблем.

## Линтеры

В конспекте используется `golangci-lint` как инструмент для запуска набора линтеров: проверки ошибок, импортов, неиспользуемого кода, сложности и других проблем.

## `gopls`

Language Server для Go. В редакторе обеспечивает, среди прочего:

- подсветку ошибок;
- переход к определению;
- поиск использований;
- автодополнение;
- подсказки.

## Чеклист

```bash
gofmt -w .
go vet ./...
go test ./...
go test -race ./...
```

А при настроенном проекте — также запуск линтера.

## Что проговорить перед собеседованием

- Зачем нужен `gofmt`?
- Чем `goimports` дополняет форматирование?
- Что делает `go vet`?
- Что такое `gopls`?
- Для чего нужен race detector?
- Что бы ты запускал перед PR?
